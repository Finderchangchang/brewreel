# 调配方：把一支参考视频调成一份可复用的配方（风格包）

English: [README.en.md](README.en.md)

在精酿 · BrewReel 里，一个风格包就是一份「配方」，从参考视频提炼出新风格的这套流程叫「调配方」（早期版本叫「风格蒸馏」，所以目录名还是 `distill/`）。

目标：看到一支好看的短视频，学它的**做法**（叙事、节奏、动效、镜头、版式），不学它的**长相**（配色、角色、招牌细节、固定句式、收尾方式），做成组件，让便宜模型只填字段就能出同样完成度的片子。

一句话标准：**同一类型，但熟悉参考片的人一眼看得出不是同一家。** 质量不能因为换皮而下降。

六步，每步有一份可复用的提示词，任何 AI 编程助手（Claude Code、Codex、Cursor……）都能照做。

| 步骤 | 产出 | 提示词 | 谁做 |
|---|---|---|---|
| 1. 拆解 | 九层拆解 + 逐拍表 + tokens 草稿 + **招牌清单** `signatures.md`（全部放仓库外） | `prompts/01-breakdown.md` | 强模型，配合 `scripts/extract-frames.mjs` 的实测数据 |
| 2. 复刻（只为学骨架，不发布） | 一支「像它」的示范片，确认哪些东西真正决定观感；**不提交、不发布** | `prompts/02-replicate.md` | 强模型 |
| 3. **再设计（换皮）** | 配色、字体处理、角色、招牌细节、文案句式、收尾方式全部换成自己的；`styles/<id>/originality.md`；`check-originality` 通过 | `prompts/redesign.md` | 强模型 |
| 4. 组件化 | `template/src/styles/<id>/` 的令牌、镜头、规格；`styles/<id>/` 的文档和规则 | `prompts/03-componentize.md` | 强模型 |
| 5. 便宜模型测试 | 便宜模型只读文档写 3 份分镜并出片，记下它写错的地方 | 直接用 `SKILL.md` 流程 | 便宜模型 |
| 6. 评审修复 | 对照参考片打分（含**混淆度** 1–10，≤ 3 才算过），列问题，修规则和组件 | `prompts/04-review.md` | 另一个模型或人 |

第 2 步和第 3 步的分工：复刻是为了**看懂**，可以先照着实测数值把骨架跑通；再设计是为了**变成自己的**，复刻阶段的配色、版式细节、占位角色在这一步全部换掉。第 3 步没过，不许进第 4 步，更不许把 `status` 改成 `stable`。

## 骨架层 vs 皮肤层

判断方法：**把它换掉，观众还认不认得出这是哪一家？** 认得出 → 皮肤，必须换；认不出、只觉得「这是一类视频」→ 骨架，可以留。

| 层 | 包括 | 处理 |
|---|---|---|
| 骨架（类型） | 叙事结构、段落顺序、节奏（BPM、每段拍数）、动效手法（回弹入场、硬切状态、逐字点亮、视差、减速当特写）、镜头语言（一镜到底、整页上滑、缩框）、版式原则（安全区、信息层级、「一主色 + 一强调色 + 一深色」这种配色结构）、互动机制（揭晓前倒数、请观众作答） | 可以保留，写进 `STYLE.md` |
| 皮肤（长相） | 具体配色（背景、主色 + 强调色组合、描边色、道具和类别色）、字体处理（字重对比、描边投影、强调手法的具体样式）、角色（造型、人设配色、服装、标志物、变身细节）、招牌细节（固定位置的小图形、固定出场方式的小人、固定形状的标记）、固定文案句式（每条都用的提问句、复听句、互动句、口号）、品牌化收尾（落版版式、网址 / logo 动画、数据卡的出场方式） | 必须重做，逐条记进 `originality.md` |

判断例子（抽象描述）：

| 参考片里的东西 | 骨架还是皮肤 | 我们可以怎么做 |
|---|---|---|
| 揭晓前倒数三拍 | 骨架（机制） | 保留倒数；倒数的**样子**自己定（进度环、格子填满、沙漏），不用和参考同色同位置的大数字 |
| 关键词用主色、答案用强调色 | 骨架（配色结构） | 保留结构；主色和强调色换成离参考色 ΔE00 ≥ 20 的自己的一组 |
| 标题旁一个固定形状、固定颜色的问号方块 | 皮肤（招牌细节） | 去掉，或换成完全不同的形式（手写波浪线、印章、括号批注） |
| 角落里探头出来的小人 | 皮肤（招牌细节 + 出场方式） | 角色只在剧情镜头出现，或换一种出场（从底部滑入、在题板上挂着） |
| 满屏主色卡 + 删除线否定错误理解 | 「否定一个错误理解」是骨架；「满屏主色卡 + 删除线」是皮肤 | 换成翻牌、盖章、对照表等其他表现 |
| 每条都说的同一句提问 / 复听 / 互动 CTA | 皮肤（固定句式） | 写 2–3 个自己的句式轮换，写进 `recipes.md` |
| 每个分区有一块展示代表内容的物件 | 骨架 | 保留；物件自己定（店招、气球横幅、橱窗、车身广告），不用和参考同款的带灯泡高架广告牌 |
| 顶部「左品牌 + 右类别 + 进度点」的固定 HUD | 「有进度指示」是骨架；这套具体组合与位置是皮肤 | 换位置和形式（底部路线条、角标里程、章节贴纸） |
| 结尾整屏缩进某种界面框 + 数据卡 | 「结尾回到产品」是骨架；这个缩框 + 数据卡的组合是皮肤 | 换收尾：落进手机屏、地图收拢成图标、翻开一本册子 |
| 拟物吉祥物 + 一个交通工具 + 一套表情 | 骨架（角色结构） | 保留结构；造型、配色、标志物全部自己画 |

## 第 1 步要的实测数据

```
node scripts/extract-frames.mjs <参考视频> --out <仓库外目录> --fps 4 --audio
```

得到 `info.json`（时长、分辨率、帧率、场景切换点、变化最大的时刻）、`frames/`（每秒 4 张）、`contact.html`（总览）、`cuts/`（每个切点后的第一帧）、`audio.wav`（找节拍、判断有没有旁白）。设 `FFMPEG` 环境变量指向完整版 ffmpeg 时还会出 `contact.jpg` 拼图。

## 第 3 步的量化检查

```
node scripts/check-originality.mjs --style <id> --ref <仓库外>/tokens.json --signatures <仓库外>/signatures.md
```

用 CIEDE2000（ΔE00）比较风格 `tokens.json` 和参考 `tokens.json`，任何一条不满足就退出码 1：

1. 主题里所有有彩色（CIELCh 色度 C* ≥ 12）离参考的每个有彩色都 ≥ 20；
2. 背景色离参考背景色 ≥ 8；
3. 主色 + 强调色不能同时落在参考某两色的 25 以内（单色都过线、组合仍然撞也不行）；
4. 近黑近白的中性色不参加第 1 条，但描边色不能和参考描边色相同；
5. 主题以外的颜色（道具色、类别色，`--extra` 加进来的角色配色文件）与参考色 < 3 算原样照搬；< 20 只提示，`--strict` 时也算失败；
6. 给了 `--signatures` 时，招牌清单里的每一条，`styles/<id>/originality.md` 都要有「已替换为：…」（整条去掉写「已删除」）。

常用参数：`--suggest` 给没过的颜色找最近的可用色；`--extra <角色配色文件>` 把写在代码里的角色 / 场景色一起查；`--svg <仓库外路径>` 出一张色块对照图。
量化检查只管颜色和记录是否齐全，角色造型、版式、句式像不像，靠第 6 步的混淆度评审。

## 版权口径（每一步都适用）

- 参考视频、截图、抽帧、角色、品牌名、网址、影视片段、参考 `tokens.json` 和招牌清单原件都**只在仓库外**。
- 仓库里只放我们自己写的拆解文字、自己画的角色和场景、自己编的示例内容；文档里写「参考了一支 X 类短视频」，不写对方品牌名。
- 拆解时把对方的品牌资产和招牌细节单独列成招牌清单（带编号），再设计时逐条写替代做法。

## 完成标准

- 便宜模型只看 `SKILL.md` + `styles/<id>/STYLE.md` + `recipes.md` 就能写出能过校验的分镜；
- 出片第 0 帧有内容和钩子，字号守底线，关键内容在安全区；
- `check-originality` 通过，`originality.md` 填完；
- 和参考片放在一起看，完成度可比，混淆度 ≤ 3：熟悉参考片的人一眼看得出不是同一家；
- 和仓库里已有的风格一眼能区分。
