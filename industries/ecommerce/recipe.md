# 电商实物（ecommerce）推荐结构

推荐结构以本文件为准。`rules.json` 的 `enabledShots` 不是白名单：没写进去的 `steps`、`meter`、`storeCard` 只要不在 `disabledShots` 里就能用。本行业只继承 `_base` 对 `beforeAfter` 的禁用。

## 1. 适用范围
普通日用品：日用百货、家居、3C数码、食品零食、生鲜、化妆品、母婴儿童、酒类。
**不做**（rejectBrief 整份拒绝）：保健食品、药品、医疗器械、特殊医学用途配方食品、烟草、电子烟。

## 2. 推荐结构

### A. 痛点解决，23.5 秒
| 镜头 | 秒 | 目的 | 字幕示例 |
|---|---|---|---|
| hook | 2.5 | 前 3 秒说痛点 | 咖啡放到中午\n就凉了？ |
| photoShot(callouts) | 4 | 实物加 3 个卖点圈注 | 316不锈钢内胆｜一键弹盖｜380ml |
| counter(measure) | 5 | 实测数据证明卖点，写条件和来源 | 95℃装满 6小时后68℃ |
| features | 5 | 3 个次要卖点 | 单手弹盖｜杯盖可拆洗｜车载杯托 |
| priceCard(card) | 4 | 可选，挂车平台默认关 | 券后59元/只 |
| endCard | 3 | 站内行动号召 | 点左下角购物车看详情 |

### B. 实测对比，23.5 秒
hook 2.5 → counter(measure) 5 → compare(subject=self，只和自家旧款比) 5 → factSheet(spec) 4 → phone(真实评价截图，隐去昵称) 4 → endCard 3

### C. 开箱清单，24 秒
hook 2 → factSheet(box，写赠品品名和数量) 5 → quickList(5 个细节) 6 → photoShot(grid，场景图) 4 → priceCard 4 → endCard 3

变体"场景种草"：hook → photoShot(grid) → features → steps → counter(count，必须带 source 和 asOf) → endCard

## 3. 钩子示例
咖啡放到中午\n就凉了？｜95℃热水装满\n6小时后还剩几度｜买保温杯前\n先看这3个细节｜拆开看看\n这个杯子里有什么｜旧款和新款\n到底差在哪｜一只手就能\n弹开的杯盖｜出租屋小桌面\n3件小物就够整洁｜跑步耳机总掉？\n看看这个耳挂｜零食囤货前\n先看配料表｜通勤、办公、露营\n同一只杯子

## 4. 镜头用法
- `chat` 只有 `brief.realQA` 有真实客服问答才能用，否则一律拦截；台词不能是"老板/老公/老婆/婆婆，便宜点"式演戏。
- `counter(measure)` 必须带测试条件（condition）和来源（source）。
- `compare` 只能和自家旧款比（subject=self），不能拿其他品牌做对照。
- `photoShot` 的商品图只能是商家实拍，不画拟真商品外形冒充实物（没图就用场景图标兜底）。

## 5. 视觉风格
白色或燕麦白浅底，商品主色 + 1 个强调色，全片不超过 3 个主色；商品图至少占画面 50%；每镜 2.5–5 秒，总长 20–30 秒。品类差异：食品暖色近景、3C 深色底高对比、家居浅木色留白。

## 6. 必备提示语
「价格以下单页为准」（priceCard 固定 footnote）；有活动期写起止日期；有划线价写"划线价为前7日最低成交价"或"厂商建议零售价"（二选一，按实际依据）；`counter(measure)` 必带测试条件和来源；有销量写来源和截止日期；非实拍画面加"动画示意"或"场景示意"。

## 7. 最容易犯的 5 个错
1. 挂购物车（douyin_cart）时又带 priceCard——2020 版规则和 2026 价格整治口径有冲突，默认不带，带了会给警告。
2. "原价129现在59直接3折"——先核对折数算得对不对，`discountMath` 会拦算错的。
3. chat 镜头演"老板便宜点"这类演戏话术——只能用真实客服问答。
4. "假一赔十""7天无理由"这类服务承诺没有依据就写上——要在 `meta.facts` 里补依据。
5. "12小时保温"这类功能数据没写测试条件——同一镜头补 `condition` 和 `source`。

## 核心动作和素材（校验会拦）
- 电商实物是实物/门店行业：核心动作用 **photoShot（商家实拍或插画场景）** 演示，过程用 `steps`。**不要用 `mockApp` 编点单页、结算页、预订页**，校验直接拦；商家真有自己小程序/店铺页的截图，用 `phone` 放截图。
- 用到的每张图先在 `meta.assets` 登记来源（merchant / illustration / screenshot）；只有 merchant 的能标「实拍」。
- 商家没照片：用插画兜底（`source: "drawn"`），会有「正式发布前补实拍」的提醒，不会拦，也不会再报「前 3 秒没有实拍」。
- `compare` 两栏写了 `level` 时，`tone: "good"` 那栏在 `meterLabel` 这把尺子上必须更优：「保温时长」越高越好，「降温速度」「麻烦程度」越高越差。
- 价格卡照 `meta.facts` 把条件写全：周末/节假日价、券后、加价、有效期、预约、不可用日期；写附加费（加床、清洁费、锅底…）就写金额，不要只写「另计」。
