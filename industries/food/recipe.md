# 餐饮（food）推荐结构

## 1. 适用范围
堂食门店、咖啡茶饮、小吃快餐。子品类（`meta.subCategory`，目前 schema 还没开放这个字段，先按下面的品类判断，写作时心里有数即可）：正餐、火锅、烧烤、自助、茶楼、咖啡、茶饮、小吃快餐、烘焙。
**不做**：外卖专营、纯预制菜复热到家、无实体门店的中央厨房品牌。

## 2. 推荐结构

### A. 团购套餐带货（抖音挂团购），21 秒
| 镜头 | 秒 | 目的 | 字幕示例 |
|---|---|---|---|
| hook | 1.5 | 用团购价开场，数字必须等于团购价 | 两个人59元\n能吃到4样招牌 |
| photoShot(hero) | 2.5 | 招牌菜 1，refs 指向依据 | 红烧牛肉面｜牛腱自家卤 |
| photoShot(hero) | 2 | 招牌菜 2，写清分量 | 手打牛肉丸｜一份6颗 |
| photoShot(clip) | 3 | 制作过程，给"熬"作证 | 牛骨汤每天熬足4小时 |
| priceCard(card) | 4 | 套餐内容、人数、限制、另收费用 | 双人招牌餐 团购价¥59 |
| reviewCard | 2.5 | 真实评价，带月份 | "汤很浓，肉给得实在" |
| storeCard(photo) | 3 | 门头、地标、营业时间 | 桂园站B口 步行3分钟 |
| endCard | 2.5 | 平台内操作 | 点视频定位看团购 |

### B. 新品上新（咖啡、茶饮），16 秒
hook 1.5 → photoShot(hero，带"新品"角标) 2.5 → photoShot(clip，萃取或熬酱) 3 → meter(口味刻度，如"甜度 3/5"，不做好喝指数) 2.5 → features(3 个能兑现的卖点) 3 → priceCard(促销价，period 必填) 2 → endCard 1.5

### C. 新店开业/到店指南，22 秒
hook(地标开场) 1.5 → storeCard(photo) 3 → photoShot(grid，店内环境) 3.5 → photoShot(hero，招牌菜) 2.5 → photoShot(hero，小份菜) 2.5 → steps(路线) 4 → priceCard(开业价，写起止日期和限制) 3 → endCard 2

变体"老店手艺故事"（偏视频号，27 秒，节奏放慢、字号加大）：hook → photoShot(clip) → steps(工序) → counter(开店年份，refs 指向营业执照) → reviewCard → photoShot(hero) → storeCard → endCard(带"按需点餐")

## 3. 钩子示例
- 两个人59元\n能吃到4样招牌
- 这碗牛骨汤\n每天熬足4小时
- 桂园站B口\n新开了一家面馆
- 今天的第一杯\n桂花拿铁上新
- 一个人吃饭\n也有小份菜
- 打工人午饭\n15元一荤两素
- 火锅团购前\n先看锅底收不收费
- 周末带娃吃什么\n这家有儿童座椅
- 第二杯半价\n只到10月7日
- 开了10年的老店\n还是那口大锅

## 4. 镜头用法
- **禁用**：`beforeAfter`（美业专属）。
- `photoShot`：没照片时换插画信息卡（暖色纸纹底 + 大字菜名 + 卖点 + 价签 + 单色线稿图标），不画拟真菜品。
- `reviewCard`：只能摘评价原文，month 必填。
- `priceCard`：`limits` 至少 1 条；子品类为火锅/自助/烧烤/茶楼时 `excludes` 必填（没有另收费用就写"无其他收费"）；抖音挂团购时不能带 `compare`（原价类字眼不能上屏）。
- "现做/现炒/现熬/手工/手打/自家卤"这类说法必须 `refs` 指向 `meta.facts` 里的依据，没有依据就别写。
- "量大管饱""分量足"建议改成具体分量，会进人工复核清单。

## 5. 视觉风格
- 正餐/火锅/烧烤：酱红 `#B3261E`、橙 `#E8741E`，炭黑底 `#1C1512`，粗黑体，每镜 1.5–2.5 秒。
- 咖啡：深棕 `#3B2A20`、奶咖 `#D9C3A5`、米白 `#F7F2EA`，每镜 2–3 秒。
- 茶饮：按主料取色配白底，每镜 1.5–2 秒。
- 小吃快餐：高饱和红黄，用小票元素，每镜 1–1.5 秒。
- 素材清单里有商家实拍时，前 3 秒内要出现实拍菜品；没有实拍就用插画兜底，不硬凑。文字放画面上 1/3 或下 1/3，不压菜品。

## 6. 必备提示语
- 出现菜品照片：「图片仅供参考 以实物为准」
- 挂团购：「以团购详情页为准」（priceCard 固定 footnote）
- 有促销：「活动时间：X月X日—X月X日」
- 出现销量数字：「数据来源：XX，统计至XXXX年X月」
- 片尾建议（非强制）：「按需点餐 拒绝浪费」

## 7. 最容易犯的 5 个错
1. 把"最正宗""全城第一"这类极限词写进钩子——换成可证实的具体说法。
2. 写"现熬""手打"却没给依据——要么补 `refs`，要么删词。
3. 抖音挂团购时把"原价68"写上画面——原价类字眼一律不上屏，只在 `priceCard.compare` 里存依据。
4. 火锅/自助品类忘了写另收费用——`excludes` 必填，没有就写"无其他收费"。
5. "老板原话"里的口头禅（扣1送、不醉不归、隔壁家都是料理包）直接照抄——这些是典型违规话术，模型要主动过滤，不是简报给什么就写什么。

## 核心动作和素材（校验会拦）
- 餐饮是实物/门店行业：核心动作用 **photoShot（商家实拍或插画场景）** 演示，过程用 `steps`。**不要用 `mockApp` 编点单页、结算页、预订页**，校验直接拦；商家真有自己小程序/店铺页的截图，用 `phone` 放截图。
- 用到的每张图先在 `meta.assets` 登记来源（merchant / illustration / screenshot）；只有 merchant 的能标「实拍」。
- 商家没照片：用插画兜底（`source: "drawn"`），会有「正式发布前补实拍」的提醒，不会拦，也不会再报「前 3 秒没有实拍」。
- `compare` 两栏写了 `level` 时，`tone: "good"` 那栏在 `meterLabel` 这把尺子上必须更优：「保温时长」越高越好，「降温速度」「麻烦程度」越高越差。
- 价格卡照 `meta.facts` 把条件写全：周末/节假日价、券后、加价、有效期、预约、不可用日期；写附加费（加床、清洁费、锅底…）就写金额，不要只写「另计」。
