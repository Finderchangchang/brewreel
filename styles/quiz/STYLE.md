# quiz 风格（答题互动）· 九层规格

> 状态：**stable**。数值以 `template/src/styles/quiz/tokens.json` 为准，本页是拆解要点的匿名化版本。
> 参考了一支答题互动类短视频（9:16，约 46 秒，学英语短语的产品推广）。参考视频、截图、角色、品牌名、网址、影视片段都不进仓库；这里只有我们自己写的拆解文字，角色、场景、示例内容都是我们自己画、自己写的。
> 老师示范：用自编短语「no big deal」按下面的逐拍表复刻了一支 46 秒的片子，和参考片逐格对照过拼图（结构、节奏、版式、动效对齐，配色和角色是我们自己的）。

核心：**先让观众猜错一次，再告诉他为什么**。和学什么无关，任何有常见误解、能出成一道选择题的东西都能套：一句外语、一个被误会的按钮、一道名字唬人的菜。

## 1. 基本参数

| 项 | 参考片实测 | 我们的做法 |
|---|---|---|
| 画幅 | 9:16，1080×1920 | 同，只支持 9:16 |
| 时长 | 45.8 秒，14 段，平均 3.3 秒一段 | 30–50 秒，5–8 镜（`rules.json` 拦） |
| 节拍 | 约 128 BPM（一拍 0.467 秒）；倒数三下间隔 0.46 / 0.48 秒 | 128 BPM，一拍 0.469 秒；时长一律写 `beats` |
| 旁白 | 几乎全程中文旁白，画面文字随旁白逐字点亮 | 没有语音合成时按固定读速点亮：旁白 6 字/秒、提问 9 字/秒、释义 8 字/秒 |
| 切点 | 场景检测只有 3 处硬切（10.8 / 20.3 / 26.4 秒），其余都是页内元素变化 | 同：页面固定，靠元素弹出和四种换场 |
| 内容占用 | y130–1500，底部约 420px 留空 | 放进 y260–1340：媒体卡 840×473（x120–960），文字守 x150–930 |

## 2. 叙事结构

骨架是「猜 → 揭 → 讲 → 练 → 互动」。前 2 秒用一个大家都会犯的误解做钩子，第 18–19 秒才揭晓，中间靠选项、倒数吊住；揭晓后靠换底色（满屏释义卡）、复证和双人小剧场三次换场撑住。

| 段 | 参考片（秒） | 作用 | 我们的镜头（拍数） | 示范片（秒） |
|---|---|---|---|---|
| 1–2 | 0.0–6.3 | 误解钩子 + 语境：第 0 帧短语已是实色、「= 误解 ?」是 60% 幽灵字、语境句前 4 个字已亮、媒体卡在位；问号块变亮色，吉祥物从卡片上沿探头，卡下语境句逐字点亮，播放键弹出 | `phraseTitle`（12–13） | 0.0–6.1 |
| 3 | 6.3–10.8 | 证据片段：卡里开演，卡下说话人 / 原文 / 译文三层字幕，关键词变主色、马克笔慢扫 | `clip`（10） | 6.1–10.8 |
| 4–7 | 10.8–20.3 | 版式跳切到提问；A/B/C 依次弹出；倒数 3-2-1；揭晓（正确项亮色打勾，错误项变灰打叉） | `quiz`（19–20） | 10.8–20.2，揭晓 18.3 |
| 8 | 20.3–26.3 | 硬切满屏主色释义卡：大号词 → ≠ 误解（删除线）→ = 正解 → 词组 → = 正解 2 | `meaningCard`（12–13） | 20.2–26.3 |
| 9 | 26.3–29.7 | 再听一遍：倒带角标、重播、「懂了」贴纸盖章、吉祥物灯泡亮起冒心 | `replay`（7–8，可省） | 26.3–29.5 |
| 10 | 29.7–37.4 | 迁移到生活：两个小人一问一答，关键词马克笔，答完跳起 | `duoScene`（14–16，可省） | 29.5–37.0 |
| 11 | 37.4–40.4 | 评论区互动：大提问 + 大号 A B C + 仿评论框打字；发送键长成亮色圆铺满全屏 | `commentCta`（7，可省） | 37.0–40.3 |
| 12–14 | 40.4–45.8 | 亮色圆缩成点，边缩边露出已经在位的整版：两行口号 + logo 卡（logo + 产品名）+ CTA 按钮 + 两个小人，定格到最后（按钮轻跳一下，不淡出、不缩成小 logo） | `brandEnd`（10–12） | 40.3–45.9 |

信息密度：段内约每 0.5 秒有一个元素在变（点亮、弹出、倒数、贴纸、角色）。最短版 5 镜（约 30 秒）：`phraseTitle → quiz → meaningCard → commentCta → brandEnd`。

## 3. 视觉系统

**色板**（每套主题 14 个色，`tokens.json` 的 `themes`）：

| 名 | 默认 `blue-lime` | 餐饮默认 `cream-tomato` | 含义 |
|---|---|---|---|
| bg | `#F4F2EA` | `#F4EFE4` | 底色，全片约 80% 时间 |
| ink | `#15203B` | `#1E1B18` | 唯一的深色：标题、描边、勾 |
| primary | `#3B57DB` | `#CF4520` | **关键词**；满屏释义卡底色；发送键；答案字母 |
| highlight | `#D3F56F` | `#FFD95A` | **对 / 答案**：问号块、正确项、倒数数字、马克笔、贴纸、按钮 |
| wrong / cross | `#A4A8AE` / `#CDB5A6` | 同 | **错**：灰字 + 暖灰 ×，不用红 |

规则：一个饱和主色 + 一个亮色 + 一个深色，全片无渐变；满屏主色卡全片只用一次。

**选配色**：`meta.theme` 可写 `blue-lime`（蓝 + 荧光绿）或 `cream-tomato`（奶油 + 番茄红 + 奶黄）。不写时按行业给默认（`tokens.industryThemes`）：餐饮 `food` 用暖色 `cream-tomato`，其余（学习、软件等）用 `blue-lime`。蓝 + 荧光绿是这种风格的识别度来源，色值是我们自己定的，不照搬参考片。

**字号**（9:16，像素；参考片的眉题 22 / 脚注 24 / 说话人 26 低于我们的下限，统一提到 28）：

| 层级 | 用途 | 字号 |
|---|---|---|
| 超大 | 倒数数字 / 释义主词 / 钩子短语 / 产品名 / ABC | 280 / 180 / 150（按宽度自动缩，最小 90）/ 150 / 128 |
| 大 | 「= 误解」行 / 释义行、CTA 提问、口号 | 88 / 80 |
| 中 | 提问 / 语境句 / 选项 | 68 / 60 / 54 |
| 正文 | 字幕、气泡 / 旁白 / 评论 / 译文 | 50 / 46 / 44 / 40 |
| 小 | 胶囊 / 眉题 / 说话人、脚注 | 34 / 30 / 28 |

字体：拉丁和中文都用粗黑（900），拉丁字距收紧 2.5%。强调只有三种：换主色（关键词）、亮色马克笔底（字高下 40%，从左往右 1.5 秒扫出）、删除线（否定）。问号单独放进亮色圆角块。

**版式网格**：问答段和标题左对齐（左边距 150，参考片是 76，我们守文字区 x150–930）；字幕、译文、口号居中。纵向分区：眉题 y270 → 标题 y306 → 媒体卡 y600（钩子位）或 y384（提问位）→ 卡下字幕或选项 → y1340 以下留空。选项卡高 108、间距 20、描边 4、圆角 26，字母圈直径 72；4 个选项时自动等比压扁放进 y1340 以内。媒体卡比文字区宽（x120–960），卡里没有要读的字伸出文字区。

**插画**：扁平平涂，统一深色描边（600 高的角色线宽 6，按比例缩放），线头圆润；无渐变、无高光，只有脚下一个浅色椭圆影；约 4.3 头身。两个角色都是我们自己画的（`template/src/styles/quiz/art/`）：主讲人（波波头 + 发箍上的小灯泡天线，**灯泡亮 = 懂了**）、搭档（毛线帽 + 卫衣）。颜色全部从当前主题取，换主题自动跟着变。

## 4. 镜头语言

页面本身不推不拉不摇、没有视差，像固定机位下的 App 界面在动。真正的「镜头」只在媒体卡里：小剧场自动切全景 / 说话人近景并慢推（台词 ≥1.2 秒时），再听一遍时倒带。

换场只有四种（`tokens.transitions`，整片渲染器 `film.tsx` 统一做）：

| 换场 | 时长 | 用在 |
|---|---|---|
| jump 版式跳切 | 1 帧，同一张卡跳到新位置，其余元素全撤，配 swish | 进 `quiz` |
| cut 硬切 | 1 帧；切到满屏主色时第一个词和原句卡已在位（不留纯色空帧） | 进 `meaningCard`、`clip`、`brandEnd` |
| dim 压暗溶解 | 3 帧 | 进 `replay` |
| pushUp 整页上滑 | 0.2 秒，easeInOutCubic，像刷信息流 | 进 `duoScene`、`commentCta` |

另有一个跨镜头的圆形擦除：评论框的发送键长成亮色圆铺满（0.1 秒），下一镜只停 1 帧就 0.24 秒缩成一个点（缓出，前两三帧就露出内容），下面的落版整版已经在位——边擦边露出内容，整屏纯色不超过 4 帧。`make.mjs` 出片后逐帧查：整屏 95% 以上一个颜色、连续超过 6 帧就算空帧，不交付。

## 5. 动效语言（参考片逐帧实测，29.97 fps，±1 帧）

| 动作 | 时长 / 参数 | 要点 |
|---|---|---|
| 幽灵字点亮 | 拉丁每词 0.37 秒，汉字每字 0.1 秒，单字淡入 2 帧 | 卡下字幕第 0 帧以 16% 排好；钩子要求第 0 帧可读：短语实色、误解行 ≥60%（`motion.hookGhost`）、语境句前 4 个字已亮 |
| 逐字打出 | 旁白 6、提问 9、释义 8、评论框 7 字/秒 | 没打到的字不显示但占位，居中文字不跳 |
| 吉祥物探头 | 0.17 秒，easeOutBack | 画在卡片后面，手扒卡沿 |
| 选项弹出 | 0.27 秒，缩放 0 → 1.05 → 1，间隔 3 拍 | 音效比画面早 0.08 秒 |
| 倒数 | 一拍一个，入场 0.13 秒，1.35 → 1 | 亮色数字 + 深色投影，叠在卡上 |
| 揭晓 | 状态 1 帧切换；正确项 0.2 秒放大到 1.03 回弹；勾叉 0.1 秒 | 揭晓落在结束前 ≥1.5 秒的整拍上 |
| 删除线 | 字出完 0.1 秒后开始，0.13 秒画完，两边各长 25px | |
| 马克笔 | 1.5 秒慢扫 | 让眼睛停在关键词上 |
| 贴纸盖章 | 0.13 秒，1.3 → 1，旋转 -8° | 配低频「咚」 |
| 冒心 | 0.4 秒，上升 120px，4 颗 | 主色和亮色两种 |
| 角色放大进场 | 0.2 秒，0.2 → 1，以脚底为锚点，两人相隔 0.1 秒 | |
| 气泡 | 0.13 秒，0.6 → 1，以尾巴尖为锚点；回答先幽灵后实 | |
| 跳起 | 0.2 秒，最高点灯泡亮起 | |
| 产品名飞入 | 0.13 秒从右侧带运动模糊 | |
| 结尾 | 整版在前 0.5 秒内入场后定格；最后 1 秒按钮轻跳、冒心，不淡出 | CTA（`meta.cta`）一直留到最后一帧 |

整体：入场都带回弹，状态切换 1 帧硬切，换场都在 0.2 秒以内（圆形擦除除外）。倒数和揭晓严格落拍，其余跟文字节奏走。

## 6. 元件库

镜头（`template/src/styles/quiz/shots/`，字段和字数上限见各自的 `.spec.json`，便宜模型的填法见 `recipes.md`）：

| 镜头 | 必填字段 | 画面 |
|---|---|---|
| `phraseTitle`（第一镜） | `phrase` ≤6、`guess` ≤6 | 眉题 + 大短语 + 「= 误解 ?」+ 媒体卡 + 探头 + 语境句 + 播放键 |
| `clip` | `lines` 1–2 句（`text` ≤20） | 沿用钩子标题，卡里开演，卡下三层字幕 |
| `quiz` | `question` ≤12、`options` 2–4 个 ≤8、`answer` | 提问、选项、倒数、揭晓 |
| `meaningCard` | `rows` 3–5 行（word / neq / eq，≤8） | 满屏主色释义卡 |
| `replay` | 全可省 | 再听一遍 + 倒带 + 贴纸 |
| `duoScene` | `context` ≤14、`ask` ≤16、`reply` ≤10 | 两个小人一问一答 |
| `commentCta` | `question` ≤12 | 大号 ABC + 仿评论框 + 2–3 条别人的评论依次弹出（`comments`，可省）+ 圆形擦除 |
| `brandEnd`（最后一镜） | `slogan` 两行 ≤16 | 口号、logo 卡（宽 780）、CTA 按钮、两个小人，定格到最后 |

字数按「汉字 1、拉丁字母半个」算，所以 `phrase` ≤6 约等于 12 个英文字母（「no big deal」算 5.5）。

元件（`parts/`）：`kit.tsx` 幽灵字 / 打字（中文按词不断行）、关键词、马克笔、删除线、问号块、勾叉、贴纸、冒心、胶囊；`media.tsx` 媒体卡、播放键、倒带角标、烧录字幕条、倒数、卡下三层字幕、钩子标题头；`cast.tsx` 角色、头像、探头、小剧场的接口层（镜头只从这里拿角色，美术换实现只改这一个文件）。

媒体卡里放什么（`scene` / `media`）：
- `office` / `cafe` / `street` / `home` / `classroom`：我们的两个角色在场景里把那句话演出来（默认 `office`）。
- `screen`：一块产品界面示意，界面里的 2–4 行字写 `screenItems`（真字，34px）；软件题材必须写（校验会拦），不写就是灰条占位，接近反面教材「空的录屏」。
- `phone`：手机演示——手指按住说话键 → 波形跳 → 松手 → 列表逐条出现 `screenItems`。为了不剧透，钩子里是待机、clip 和 quiz 里只演到按住（列表是「？」占位），`replay`（再看一遍）才演出结果。适合「按住 / 点一下之后发生什么」这类功能竞猜。
- `meaningCard` 下半屏有一张「原句卡」（clip 最后一句 + 译文，关键词马克笔），和释义行一起垂直居中；`duoScene` 的小人放大到 y≈700–1400，译文放进气泡第二行。
- `media`：用户自己有版权的截图或视频（登记在 `meta.assets`）；截图放进圆角卡、叠字幕条，避开「放大录屏」。

## 7. 声音

- 配乐轻快（约 128 BPM）：开头只有稀疏铺底，揭晓瞬间鼓组进入（参考片低频约 +15 dB），释义段后段停鼓留白，结尾和弦。
- 音效由各镜头的 `sfx()` 按同一张时间表给出，和画面对得上：

| 镜头 | 音效 | 对应画面 |
|---|---|---|
| phraseTitle | tick / pop / pu / tap | 误解行 / 问号块 / 探头 / 播放键 |
| clip | ding | 关键词亮起 |
| quiz | swish / pop×选项数 / tick×3 + whoosh / ding + thud | 跳切 / 选项 / 倒数 / 揭晓 |
| meaningCard | thud / pop / swish | 切满屏 / 每个词 / 删除线 |
| replay | swish / pu / whoosh / thud + bell | 溶解 / 探头 / 倒带 / 贴纸 |
| duoScene | swish / pop×2 / pu + bell | 上滑 / 两个气泡 / 跳起 |
| commentCta | swish / pop / tick×3 / whoosh | 上滑 / 字母 / 打字 / 圆形擦除 |
| brandEnd | whoosh / pop / swish / pu / bell | 缩点 / logo / 产品名 / 小人 / 锁定 |

- 卡点：倒数和揭晓严格落拍；音乐最大的变化放在揭晓，是全片情绪最高的一刻。

## 8. 可变与不变

**固定（便宜模型不碰）**：色板和颜色含义、幽灵字机制和读速、版式网格、动效参数、四种换场、段落顺序、角色造型、音效映射。

**便宜模型要填的**（其余自动推导，逐镜字段和字数见 `recipes.md`）：

| 字段 | 在哪 | 说明 |
|---|---|---|
| `product` / `cta` / `action` / `industry` / `theme` | meta | 产品名（落版大字）、行动号召（按钮，≤14 字，更长就给 `brandEnd.button` 写其中的关键几个字）、配色（可省，按行业默认） |
| `phrase` + `guess` | phraseTitle | 被误解的说法 + 大多数人的第一反应（陷阱项） |
| `context`、`scene`、`screenItems` | phraseTitle | 语境一句（不揭晓）；媒体卡里演什么；界面示意里的字（scene 是 screen / phone 时必填） |
| `lines` + `key` | clip | 1–2 句台词，最后一句原样包含 `key`；**只露短语 / 功能名 / 菜名，不许说出答案或效果**（text、zh、数字都算） |
| `question` + `options` + `answer` | quiz | 提问、2–4 个选项（含 `guess` 原文）、正确项序号 |
| `rows` | meaningCard | word / neq（误解）/ eq（正解），3–5 行 |
| `context` + `ask` + `reply` + `key` | duoScene | 生活化一问一答 |
| `question` | commentCta | 「你刚才猜的哪个？」这一类 |
| `slogan`（+ `badge`） | brandEnd | 两行口号 |

**自动推导**：片段沿用钩子的标题和场景；提问卡的烧录字幕 = 片段最后一句里含 `key` 的那半句（或 `quiz.quizLine`，≤12 字，不含答案）；`screenItems` 写一次全片沿用；再听一遍的台词、关键词、正解胶囊沿用 clip 和 meaningCard；评论区的字母数和答案取自 quiz，预填评论默认「我选了 <陷阱项字母>……」；落版产品名取 `meta.product`、按钮取 `meta.cta`。

## 9. 规则（都写成了校验）

声明式（`styles/quiz/rules.json`）：总长 30–50 秒；5–8 镜；必须有 `phraseTitle`、`quiz`、`meaningCard`、`brandEnd`；每种镜头最多 1 次；顺序固定 `phraseTitle → clip → quiz → meaningCard → replay → duoScene → commentCta → brandEnd`；第一镜 `phraseTitle`、最后一镜 `brandEnd`（`style.json`）。

字段级（各镜头 `.spec.json`）：必填、字数上限、选项和释义行的条数、`scene` 枚举、时长范围。

跨字段（`styles/quiz/checks.mjs`，报错都带改法）：
- Q1 选项 2–4 个、不重复；`answer` 是合法序号。
- Q2 钩子的 `guess` 必须原样是一个选项（陷阱项），且不是正确答案。
- Q3 错误选项不写阿拉伯数字；具体数字只给正确项，并且要出自 `meta.facts`（全片数字核对会拦没有来源的数字）。
- Q4 `clip` / `duoScene` / `replay` 的 `key` 必须是所在台词的子串（大小写一致）。
- Q5 片段的 `key` 要和钩子短语对得上（提醒）。
- Q6 释义卡第一行是 word、恰好 1 行 ≠、至少 1 行 =；≠ 行和钩子误解、第一个词和钩子短语要对得上（提醒）。
- Q7 评论区的 `letters` / `answer` 写了就必须和 quiz 一致；`commentCta` 后面紧跟 `brandEnd`（提醒）。
- Q8 落版要有产品名；必须有行动引导（`meta.cta` 或 `brandEnd.button`），写了 `button` 要和 `meta.cta` 对得上；按钮文案 ≤14 字。
- Q9 提问到揭晓 6–8 秒（quiz 写 17–21 拍，提醒）。
- Q10 出题前不剧透：钩子语境句、clip 台词（`text` 和 `zh`）、quiz 卡里的字幕条，都不许含正确答案、释义卡 = 行（子串或去掉标点后一半以上重合都算），也不许含它们里的数字。
- Q11 数量题（题目问「几个小时 / 多少 / 几次 / 几天」）：每个选项都要是数量；错误项用中文数字（「一小时 / 6 小时 / 十二小时」），正确项的阿拉伯数字出自 `meta.facts`。
- Q12 `scene` 是 `screen` / `phone` 就要写 `screenItems`；`industry: "software"` 必须写。
- Q13 有 `clip` 没 `replay` 提醒（少了「再听一遍」这一拍）。

行业合规照常生效（`industries/<行业>/rules.json`）：教育类不承诺提分；餐饮类不写极限词和功效，「熬了几小时」这类数字要有 `meta.facts`。注意「你第一反应选的哪个」里的「第一」会被广告法极限词规则拦，评论区提问写「你刚才猜的哪个？」「你一开始猜的哪个？」。

## 证据片段的替代方案（参考片用的是影视片段，我们不用）

1. **插画小剧场**（默认）：我们的角色在媒体卡里演出那句话被说出来的瞬间（嘴动、点头、说话人近景），不需要外部素材。
2. **产品界面示意**（`scene: "screen"`）或截图：放进圆角卡，叠字幕条和贴纸，避开「放大录屏」这个反面教材。
3. **用户自备视频**：版权由用户声明，登记在 `meta.assets`。

## 必须避开的参考片资产

参考片的产品名、网址、logo、顶部品牌小标、「网址里的点变句号」的落版、那对吉祥物的造型和状态道具的具体样子、影视片段及其片名和角色名。机制（幽灵字、探头、倒数、满屏释义卡、圆形擦除）可以借，字和图形一律是我们自己的；我们的落版只放产品名，不放网址。

## 适合 / 不适合

- 适合：有一个常见误解、能出成一道选择题的产品——外语短语、被误会的功能（「归档 = 删掉了？」「双链 = 复制一份？」）、名字唬人的菜（「老火汤 = 大火煮？」）、反常识的知识点。
- 不适合：找不到可以出题的误解、只想罗列卖点或讲价格的（用 `cards`）；想展示一个完整世界或多个类别的（用 `journey`）。
