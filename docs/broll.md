# 口播配画面（实验）

[← 返回 README](../README.md) · [English](broll.en.md)

给一段真人口播配上解释用的画面。画面有两种：

- **动效画面**：免费。关键词、清单、步骤、数字、对比五种卡片，上面的字全部从口播原话里摘，说到哪个字亮到哪个字。
- **AI 画面**：用 MiniMax H3 生成的小场景，花钱，要人审过。有积木风、黏土定格、分层纸艺、手绘线稿几种风格，全片同一个机器人。

模型只写 `broll.json`：哪几句配画面、配哪种。时间、费用、生成和合成都由脚本做。

## 适合谁

已经有真人口播，想在讲步骤、讲数字、讲对比、讲物件的句子上加一段解释画面的作者。开场、收尾和讲自己感受的句子继续露脸。

## 一条命令上手

先按 [安装与上手](quickstart.md) 装好依赖（`template` 目录里 `npm install`，再 `pip install numpy scipy imageio-ffmpeg`）。从 v0.8 升级的，要在 `template` 目录重新跑一次 `npm install`，装上转写组件。

口播配画面要**完整版 ffmpeg**（转码、占位画面、片段检查、拼图都要用）。Remotion 自带的那份是精简版，缺很多滤镜，不够用。`pip install imageio-ffmpeg` 最省事；也可以自己装 ffmpeg 放进 PATH，或者设环境变量 `FFMPEG` 指向它。没装的话，命令一开头就会停下告诉你，不会等转写完才失败。

新建一个项目目录，把口播视频改名为 `talk.mp4` 放进去，然后：

```
node scripts/talk.mjs <项目目录> --out <仓库外目录>
```

它做三步。前两步做过就跳过；出片每次重做，但原片、字幕、`broll.json`、生成片和合成代码都没变时，直接用上次的成片。所以可以一直重复跑同一条命令：

1. **转写**：没有 `talk.srt` 就在本机转写出一份。第一次要下载约 240MB 的识别模型，之后不再下载。已有 `talk.srt` 永远不会被覆盖。
2. **写 `broll.json`**：交给便宜模型写，要先设好 `DEEPSEEK_API_KEY`（或 `LLM_API_KEY`）。校验没过，会把报错原文交回模型再写，最多 3 轮。已有 `broll.json` 就跳过，加 `--rewrite-broll` 才重写。
3. **出片**：动效画面直接画出来；AI 画面先用纯色占位，不花钱。

第一次跑完，打开输出目录里的 `video.mp4` 和拼图 `sheet.png` 看节奏。默认 AI 画面最多 2 段，其余要配画面的句子用动效画面或留脸；想改上限加 `--max-ai 1` 之类，再加 `--rewrite-broll` 重写（重写时不要带 `--yes`：新方案先看估价）。

`--rewrite-broll`、`--only`、`--force-redo` 只该生效一次。脚本停下时会把下一条命令完整印出来（已经去掉这几个），照抄那一条就行。

转写校对时拿不准、还没人核对的字（`talk.fixes.txt` 里「只提示」的那些），不会被做成动效卡片；命令跑完也会再提醒一次。听一下原片，错了就改 `talk.srt`；改完要按新字重写 `broll.json` 就加 `--rewrite-broll`。

想先改字幕再往下走：先只跑转写，改好 `talk.srt`，再跑上面那条命令。

```
node scripts/broll/transcribe.mjs <项目目录>
```

没有 DeepSeek key 也能用：让 AI 编程助手照 [`broll/SKILL-broll.md`](../broll/SKILL-broll.md) 写 `broll.json` 放进项目目录，再跑同一条命令。v2 写法的完整示例在 [`examples/talk/motion/broll.json`](../examples/talk/motion/broll.json)，用来参考写法；仓库里没有示例口播视频，想直接拿它试跑，先跑 `node tests/broll/demo.mjs` 生成一段 20 秒的测试口播。

### 真生成 AI 画面

> **这一版还不能真生成。** 四个正式风格的参考图还没出，用它们真生成会在提交前停下（退出码 2，没花钱）。现在 AI 画面只能用占位预览，动效画面照常出。参考图由维护者出好、随新版本发布后，下面的命令才能用。

占位版看着没问题，再换成 MiniMax H3 真生成。先设好 `MINIMAX_API_KEY`。

```
node scripts/talk.mjs <项目目录> --out <仓库外目录> --provider minimax-h3 --dry-run
node scripts/talk.mjs <项目目录> --out <仓库外目录> --provider minimax-h3 --yes
```

第一条只印估价，不花钱。确认后跑第二条。生成完要人看过审片页、自己批准，才能出正式片（见下面的「审片关卡」）。`--dry-run`、`--yes` 只作用于出片这一步，前两步做过就跳过。

真生成以后，同一个 `--out` 的每条命令都要带 `--provider minimax-h3`。漏写了，脚本会停下（退出码 2），不会把付费片段换成占位片；只想看占位排版就换一个 `--out`。

### 常用参数

| 参数 | 作用 |
|---|---|
| `--out <目录>` | 输出目录，必填，不能在仓库里面 |
| `--provider placeholder\|local\|minimax-h3` | AI 画面从哪来，默认用 `broll.json` 里写的（便宜模型写的是 `placeholder`） |
| `--dry-run` | 只校验、出计划和估价，不生成 |
| `--yes` | 确认花钱，真生成 |
| `--draft` | 还没审片时先出一版草稿，AI 画面上标「B-roll 未审」 |
| `--style <风格>` | 写 `broll.json` 时用的主风格，默认 `wood-blocks` |
| `--max-ai <段数>` | 写 `broll.json` 时 AI 画面最多几段，默认 2 |
| `--budget <元>` | 写进 `broll.json` 的预算，默认 20 |
| `--captions add\|none\|burned` | 字幕怎么处理，默认 `add` |
| `--lang auto\|zh\|en\|yue\|ja\|ko` | 转写语种，默认 `auto` |
| `--terms "词1,词2"` | 专有名词，帮转写校对认对 |
| `--no-fix` | 转写后不让 DeepSeek 校对 |
| `--rewrite-broll` | 已有 `broll.json` 也重写。通过校验才替换，旧的备份成 `broll.json.bak-<时间>`；不能和 `--yes` 一起用 |
| `--only b03` | 只重做这一段 AI 画面（每带一次就重做一次、花一次钱，重做完就去掉） |
| `--concurrency <1–12>` | 同时提交几段，默认 3 |
| `--force-redo` | 同一段第 3 次重做时要加 |

`--style`、`--max-ai`、`--budget`、`--captions` 只在写 `broll.json` 那一步用。`broll.json` 已经有了还想改，直接改文件，或加 `--rewrite-broll`。

## 分步命令

一条命令其实是把下面几步串起来。想一步一步看，按顺序跑：

```
node scripts/broll/transcribe.mjs <项目目录> [--lang auto] [--terms "词1,词2"] [--no-fix] [--force]
node scripts/broll/list-cues.mjs <项目目录>
node scripts/broll/llm_broll.mjs <项目目录> [--style wood-blocks] [--budget 20] [--captions add] [--max-ai 2] [--dry-run]
node scripts/broll/validate.mjs <项目目录> [--max-ai 2]
node scripts/make-talk.mjs <项目目录> --out <仓库外目录> [--dry-run] [--provider minimax-h3] [--yes] [--draft]
node scripts/broll/review-sheet.mjs <项目目录> --out <仓库外目录>
node scripts/broll/approve.mjs <项目目录> --out <仓库外目录>
```

`llm_broll.mjs` 加 `--dry-run` 只打印拼好的提示和估算 token，不调接口。`make-talk.mjs` 不自己转写：项目目录里没有 `talk.srt` 时它会停下，告诉你先转写。

## 两种画面

| | 动效画面 | AI 画面 |
|---|---|---|
| 写法 | `"source": "motion"` | `"source": "ai"` 或不写 |
| 费用 | 不花钱 | 按秒计费，见「费用」 |
| 画面上的字 | 全部照抄原话，脚本逐字核对 | 不放字（生成画面里的字不可靠） |
| 审片 | 不用审 | 要人看过、自己批准 |
| 角标 | 没有 | 出现时角落标「AI 生成画面」 |
| 每段长度 | 1.8–12 秒 | 2.5–12 秒 |

### 动效画面的五种卡片

| 模板 | 什么时候用 | 画面 |
|---|---|---|
| `keyword` | 一句要观众记住的话 | 大字关键词（占画面宽度约八成，长了两行），说到哪个字亮到哪个字，重点词扫一道马克笔 |
| `checklist` | 列两到四样东西 | 清单，说到哪条哪条出来打勾 |
| `steps` | 讲先后 | 台阶式步骤，说到第几步亮第几步（积木上的点数表示第几步） |
| `counter` | 报一个确定的数 | 数字滚动，说完这个数时落定 |
| `compare` | 前后、两种做法对比，先说旧的、后说新的 | 竖版上下两张卡（横版左右两栏），后说的一边胜出。先说新做法的句子别用它 |

卡片上的字必须是原话里连着的几个字，不能改写；摘词前面的否定（不用、不要、不会、don't……）要一起摘；要显示的数字用 `counter`，而且要原话里真说了，隔着空格、换行或分句的两个数不会被拼成一个。所以**转写错的字会照样上屏**：出片前看一眼 `talk.srt`，错字直接改。卡片说完最后一个字后，后面是静音的话会多停一会儿再收。

摆法：动效画面默认 `split`（上 60% 卡片、下 40% 真人），横版用 `pip`，说话的人一直在画面里；`keyword` 不能用 `full`，`full` 只给 3 条以上的清单和步骤，校验会拦。配色和质感跟着主风格走：积木风是暖木色桌面、米白卡片、浅蓝灰和暖橙的木积木，黏土定格是暖粉彩，分层纸艺是米白纸加几层彩纸，手绘线稿是白纸墨线；背景有很淡的纹理和慢慢漂的形状，装饰只放在字和字幕以外的边角，不加字。

进出场：真人只有一个画面，`split` 从全屏收到下方、卡片从上面推下来，`pip` 收进右下角圆窗（动效段的圆窗大一点、脸也放大一点，带一圈卡片色描边），出场倒放，不会叠出两张脸。`keyword` 段的字幕和大字说的是同一句时，字幕只留多出来的那几个字，或者不显示。数字是钱（元、块、¥……）又有旧价时不滚动，在说出新价的那一刻直接翻牌，不出现原话里没有的中间价；没有旧价时只在说出来之前滚 0.6 秒。

### AI 画面的风格

| 风格 | 名字 | 适合 |
|---|---|---|
| `wood-blocks` | 积木风（默认，木头积木） | 什么都能配，最适合讲步骤、讲数量、讲一样东西 |
| `clay-stopmotion` | 黏土定格 | 动手做事、点一个地方、给气氛 |
| `paper-layers` | 分层纸艺 | 讲道理、点一个场景、做对比 |
| `ink-sketch` | 手绘线稿 | 讲道理、做对比、讲数量，最适合当副风格 |
| `brick-diorama` | 塑料积木（实验） | 实验风格，不是默认，生成画面会出凸点，不建议用 |

一部片的 AI 画面最多用两种风格：主风格 `style`，加一个可选的副风格 `styleAlt`（只能选主风格搭得上的）。机器人的形状和颜色写在 `broll/character.json`，所有风格共用；风格只决定它用什么材质做。每种风格能做哪些事、能用哪些镜头、参考图出了没有，见 [`broll/styles/README.md`](../broll/styles/README.md)。

某个风格还没有参考图时，用它真生成会在提交前停下（退出码 2，没花钱），并告诉你换哪个风格、或改成动效画面。用 `placeholder` 预览不受影响。这一版四个正式风格都还没有参考图。

## 三种放法

| mode | 画面 |
|---|---|
| full | 画面盖满 |
| pip | 右下角圆窗露脸，圆窗大小跟着画面大小缩放（动效段大一点） |
| split | 上面 60% 是画面，下面 40% 是脸。只给竖版 |

## 字幕

| captions | 意思 |
|---|---|
| add | 按 `talk.srt` 把字幕加到成片上 |
| none | 不加字幕 |
| burned | 口播里已经烧了字幕。只能用 `split`，免得再盖住。横版原片加 `burned` 这一版不支持（`split` 只给竖版），改用 `none` |

`full` 和 `pip` 的字幕在画面下方 1/4；`pip` 段的字幕在圆窗左边放不下时，整段挪到圆窗上方、用满宽度。`split` 的字幕贴在分界线上方，两行字幕会整体往上挪，不压脸。一行字稍长放不下时，字号会缩一点，不让末尾剩一两个字单独成行。

## 转写

- 用的是本机的 SenseVoice 识别模型（通过 sherpa-onnx 运行），不联网、不花钱。模型第一次下载约 240MB，按顺序试魔搭、HuggingFace、hf-mirror 三个源，断了能续传，sha256 对不上的文件不收。
- 模型放在全局缓存里，所有项目共用：Windows 是 `%LOCALAPPDATA%\brewreel\asr`，macOS / Linux 是 `~/.cache/brewreel/asr`。环境变量 `BREWREEL_ASR_DIR` 改缓存目录；`BREWREEL_ASR_MODEL_DIR` 指向你手动下载好的目录（里面放 `model.int8.onnx` 和 `tokens.txt`），就不再下载。
- Windows 上下完模型后，第一次加载会多等约 30 秒。
- 语种默认自动识别。普通话被认成粤语、日语时，用 `node scripts/broll/transcribe.mjs <项目目录> --lang zh --force` 重转。
- 有 `DEEPSEEK_API_KEY`（或 `LLM_API_KEY`）时，转写完会请便宜模型校对：模型只交「哪个字改成哪个字」的补丁，脚本按读音规则决定改不改。涉及数字、否定、反义的改动只提示、不改；改成专有名词也要读音接近才改。改了什么、哪几句请你听一下原片，都写在 `talk.fixes.txt`。只提示的那几处字不会被做成动效卡片，改过那一句就算核对过。不要校对加 `--no-fix`。
- 同一个视频放进两个项目各转写一次，校对结果可能不一样（模型每次回答会有出入）；同一个项目重跑用的是缓存，结果不变。
- 专有名词（产品名、人名）可以写进项目目录的 `talk.terms.txt`，一行一个；或者用 `--terms "词1,词2"`。
- 已有 `talk.srt` 永远不覆盖。要重转加 `--force`：旧字幕先改名为 `talk.srt.bak-<时间>`，同一个视频不重新识别。
- `talk.srt` 可以随便改错字，但写好 `broll.json` 之后**不要拆句、并句**：句子号会错位。脚本记下了当时的分句，分句一变校验就会拦下，让你重写 `broll.json`。
- 转写缓存、分句记录、转码后的原片都放在项目目录的 `.brewreel/` 里。这个目录可以删，删了也能出片，只是动效卡片的逐字时刻会改用估算、分句检查也跟着没了。

自己有字幕也可以直接放 `talk.srt`（剪映等软件导出的 SRT），脚本就不转写。

## 原片自动转码

手机直出的口播常见 HEVC 编码、可变帧率、单声道、旋转标记、29.97 这类非整数帧率。出片前脚本会自动转成 H.264、恒定帧率、双声道的一份，存在项目目录的 `.brewreel/` 下，原片一个字节都不动。转过一次之后直接用缓存。已经是 H.264 恒定帧率的原片不转。

## 费用

只有 AI 画面花钱，动效画面和占位画面都不花钱。花钱前一定先印估价：超过 `budgetYuan` 就停下；没超也要加 `--yes` 才生成。估价同时印出 AI 视频一共多少秒。

MiniMax 的 key 有两种，扣法不一样：

| | 按量付费的 key | 订阅套餐的 key（`sk-cp-` 开头） |
|---|---|---|
| 怎么扣 | 按秒扣余额 | 不能按量付费。H3 视频不在套餐额度里，扣的是积分 |
| 价格 | 768P 0.5 元/秒，2K 0.8 元/秒 | 768P 约 70 积分/秒（2026-10 实测），2K 没实测 |
| 估价显示 | 「AI 视频共 N 秒，按价目表 X 元」 | 多一句「约 N 积分（订阅 key，从积分扣，以 MiniMax 后台为准）」 |
| 预算闸门 | 按元拦 | 也按元拦（价目表折算），积分只是多显示一行 |

- 价目表是脚本里写的，不是接口回执（回执里没有金额）。实际扣费以 MiniMax 官网和后台为准。
- 每段生成秒数由脚本把窗口向上取整，再夹到 4–15 秒。默认最多 2 段 AI 画面，每段最长 12 秒：768P 一部片的 AI 画面大约 2–12 元，订阅 key 大约 280–1680 积分。
- 风格参考图（image-01）每张 0.025 元，由维护者出好随仓库发，普通用户不用出。

## 审片关卡

`minimax-h3` 的正式片，每段 AI 画面都要人看过。

1. `node scripts/broll/review-sheet.mjs <项目目录> --out <仓库外目录>`
2. 用浏览器打开输出目录里的 `review.html`。每段一行：原句、风格、提示词、开头 / 中间 / 结尾三帧、费用。最上面一条把每段 AI 画面的中间帧并排放，一眼看出角色和材质前后是否一致。动效段标「动效，不用审」，列出屏幕上的字。
3. 人自己跑 `node scripts/broll/approve.mjs <项目目录> --out <仓库外目录>`
4. 再跑同一条命令，出正式片

AI 助手不许替人运行 approve，`talk.mjs` 也永远不跑它。批准记录绑定 `broll.json` 里 AI 画面的部分和每段生成片的 sha256，改了就要重新审；只改动效段不用重审。还没审、先看合成效果，加 `--draft`：AI 画面出现时右上角写「B-roll 未审」。

`placeholder` 和 `local` 不花钱，不用审。

中断了用同一个 `--out` 再跑：已经提交过的段只查询，不重新提交、不重复花钱。「再跑同一条命令」时去掉 `--only`、`--rewrite-broll`、`--force-redo`（脚本印出的下一条命令已经去掉了）。

| `broll.plan.json` | 计划：每段的时间窗、来源、风格、费用 |
| `manifest.json` | 交付清单：用了哪个风格、花了多少、字幕是自动转写还是自己给的、原片有没有转码 |
| `ledger.json` | 账本（只有 AI 画面）：task id、实际秒数、费用 |
| `review.html` / `broll.review.json` | 审片页和批准记录 |

## 已知限制

- **实验功能**：还没有用大量真人口播出过完整样片。成片当初稿，发布前整片看一遍。
- **凸点可能仍会偶发**：新风格的提示词只写想看到的东西，不提凸点，但生成模型偶尔还是会画出带圆点的积木，发布前在审片页逐帧看。`brick-diorama` 会稳定出凸点，只为老项目保留。
- **四个新风格的参考图还没出**：这一版 AI 画面不能真生成，只能用 `placeholder` 排版；参考图由维护者出好随仓库发。
- **v0.8 的老文件改成 version 2 要重新花钱**：v2 的提示词和请求都变了，已经生成过的 AI 段会重新生成。老文件留 version 1 照常能跑。
- **每段 AI 画面单独生成**：共用的角色规格、参考图和 `link: continue` 能让几段看着更接近，但造型和颜色仍可能有出入，不保证段与段完全连贯。
- **AI 画面最多两种风格**：一个主风格加一个副风格；不能每段换一种。
- **生成画面里的文字不可靠**：要准确的字请用动效画面。
- **动效画面的字照抄转写**：转写错的字会上屏，出片前看一眼 `talk.srt`。
- **英文转写只用合成语音测过**：没测过真人英文口播和口音。英文口播的数字要是阿拉伯数字才能做数字卡片。
- **macOS 没有实测转写**；Linux、没装 VC++ 运行库的干净 Windows 也没测过。魔搭以外的两个下载源没有实机测过。
- **口播带背景音乐时**，转写找不到停顿，切句和时间会不准。
- **10-bit HDR 的手机片**只转了像素格式，没做色调映射，颜色可能发灰。
- **订阅 key 的 2K 积分价没实测**，估价只写「以后台为准」。
- **便宜模型写 v2 的 `broll.json` 和转写校对**，还没用 DeepSeek 大量实测。
- DeepSeek Harness 插件这一版没有接这个能力。
