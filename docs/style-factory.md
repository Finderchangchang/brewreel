# 风格工厂

[← 返回 README](../README.md) · [English](style-factory.en.md)

一句话描述一个 AI 画面风格，脚本自己写 `style.json`、出参考图、看图打分、挑一张、再出一张静态试拍。人只在最后看汇总页，自己决定收不收进风格清单。

看图打分只是第一道筛。它会看错。最后要人看。

## 一条命令

先看将要发送的请求（不调接口，不花钱，退出码 0）：

```
node scripts/broll/new-style.mjs --id demo-watercolor --name 水彩绘本 --desc "水彩晕染、纸纹、柔和暖色"
```

确认之后真跑（DeepSeek 写配置，MiniMax 看图，image-01 出图）：

```
node scripts/broll/new-style.mjs --id demo-watercolor --name 水彩绘本 --desc "水彩晕染、纸纹、柔和暖色" --yes
```

可选参数：

| 参数 | 作用 |
|---|---|
| `--from 参考图` | 先把这张图描述成材质、色调、光线的文字，再交给写配置的模型。图本身不进风格包。 |
| `--n 3` | 每张参考图出几张候选。1 到 4，默认 3。 |
| `--retries 1` | 这一张的候选全是 fail 时，只改这一张的出图提示再出一轮。默认 1，最多 3。有 pass 或 unsure 就不重出。 |
| `--video` | 再做一段 4 秒 768P 的视频试拍。必须同时加 `--yes` 才会提交。提交前先写下「正在提交」，拿到 task id 立刻记下。再跑只要 state 里有 task id，就只查询或下载，不重新提交。 |
| `--video-redo` | 上次视频任务失败了，或上次提交没有确认结果、人已经核对过可以再交时才用。会再花约 280 积分。不加上这个，失败的任务不会自动重做，没确认的提交也不会自动再交。 |
| `--human-ok` | 只决定要不要发起新的提交。参考图是「需要人看」时，默认不提交。加上这个才允许新提交。只解除这一条。已经有 task id 时，不加它也继续查询，不清掉 task id。 |
| `--batch 清单.json` | 清单是 JSON 数组，每项 `id`、`name`、`desc`，可选 `from`。一项失败不影响下一项。 |
| `--max-video 3` | 和 `--batch --video` 一起用。最多提交几条视频，默认 3。开跑前打印合计，超出就停。 |
| `--state-reset` | 草稿里有 `state.json.bad-*`，或 state 是空的、缺 stages、但出图或视频还在时，人检查过再加。脚本把 bad 文件改名为 `.checked-<时间>` 后才继续。不加就拒绝出图和视频提交。 |

`id` 用小写英文和短横线，不能以下划线开头。已经发布的风格不会被覆盖。同一个草稿同时只跑一个进程：开始时独占创建 `run.lock`，写入 pid 和开始时间。锁还在而且那个 pid 活着，就退出，提示这个风格正在另一个进程里跑。pid 已经没了就删掉残留锁再继续。正常结束、出错退出和 Ctrl+C 都会放开这把锁。

## 各阶段

草稿落在 `broll/styles/_drafts/<id>/`。下划线开头的目录不进风格清单。做过的阶段再跑会跳过。改了 `--desc` 不会自动重写，先删掉这个草稿目录再跑。

1. **写配置**。DeepSeek 按这句话写 `style.json`。要过现有的 `lintStyle`，还要过 IP / 禁用词检查。不过就把报错原文回喂，最多 3 轮。`pairsWith` 先空着，人审的时候再定。提示词只写想看到的东西：角色图写「头顶是光滑圆顶」，不写「不要天线」。
2. **出参考图**。image-01 出角色图和材质图，每张 `--n` 张候选。
3. **挑图**。每张候选打分，结论是 pass、fail、unsure 三档。先取 pass 里软分最高的一张。没有 pass 时，取 unsure 里软分最高的，汇总页标黄「需要人看」。全是 fail 才改这一张的提示再出，最多 `--retries` 轮。仍不过就停下，退出码 1，报告写卡在哪、建议怎么改。
4. **静态试拍**。出一张「机器人把一块方块推到桌面中间」的图，按抽帧规则打分。fail 或 unsure 都不建议花视频的钱。没加 `--video` 时，这一步没过仍然把草稿交出来等人看，退出码 0。
5. **视频试拍**（可选）。H3，4 秒，768P，固定动作「把一块方块推到桌面中间」。每 0.5 秒抽 1 帧，共 8 帧，有一帧 fail 或 unsure 就没过。静态试拍没过、或参考图是「需要人看」且这次没有 `--human-ok`、也没有已保存的 task id 时，不提交。`--human-ok` 只决定要不要发起新的提交，不解除别的拦截，也不清掉已有 task id。提交前先看 ffmpeg 在不在，缺了就退出，不花钱。提交前把 `state.json` 的 video 写成 `{status:'submitting', at}`。接口返回 task id 立刻写成 `{status:'submitted', taskId}` 并打印。再跑时只要有 task id，任何一次带 `--video` 的命令都只查询或下载；不带 `--human-ok` 也不覆盖、不清空这个 task id。`clip.mp4` 已经在就只抽帧。重跑看到 `submitting` 且没有 task id：不自动提交，退出码 2，提示上次提交没有确认结果，可能已经扣费，先去 MiniMax 后台看视频任务列表，确认没有提交成功再加 `--video-redo`。轮询超时或任务还在生成：state 保持 `submitted` 和 task id，退出码 3，提示稍后再跑同一条命令继续查询，不会重新提交。只有服务端明确失败才记成失败。失败后不自动重做，要重做加 `--video-redo`（会再花约 280 积分）。`state.json` 读坏了不当成全新开始：先把坏文件改名成 `state.json.bad-<时间>`，退出码 2，提示文件损坏和备份路径，这次不发起任何付费提交。目录里只要还留着 `state.json.bad-*`，或者 state 是 `{}`、缺 stages、但已经有出图或视频，再跑仍拒绝，并指出备份或这些产物；人检查过之后加 `--state-reset` 才继续。服务端明确拒绝（余额不足、鉴权失败或 HTTP 4xx）会清掉提交标记，提示原因（余额不足就去充值），直接重跑即可。网络断开、超时、5xx 才保留 `submitting`。写「正在提交」之前会再读一次磁盘，发现已经有视频状态就停下。加了 `--video` 但视频没过，退出码 1。

## 花钱

| 调用 | 什么时候 | 闸门 |
|---|---|---|
| DeepSeek 写配置、改提示 | 写配置、挑图失败后重写这一张 | `--yes`。密钥 `DEEPSEEK_API_KEY`（或 `LLM_API_KEY`） |
| MiniMax 看图 | 描述参考图、给候选和抽帧打分 | `--yes`。走订阅套餐额度。密钥 `MINIMAX_API_KEY` |
| image-01 出图 | 参考图候选、静态试拍 | `--yes`。套餐额度。按价目表一张 0.025 元 |
| H3 视频 | 4 秒 768P | 同时 `--video` 和 `--yes`。真调前打印「约 280 积分 / 按价目表约 2 元」。批量再打印合计，默认最多 `--max-video 3` 条 |

没有 `--yes` 只打印将要发送的请求：不带密钥，图片按字节数略写。

看图接口是 `POST <base>/v1/chat/completions`，Bearer `MINIMAX_API_KEY`，图片用 jpeg 的 base64 data URL。base 默认 `https://api.minimaxi.com`，`MINIMAX_BASE_URL` 可改（只收 https；本机测试可以用 localhost）。模型默认 `MiniMax-M3`，`BREWREEL_VISION_MODEL` 可改。

## 看图怎么判

模型按固定检查表交 JSON，每项带一句理由。脚本判三档，不信模型的总评。温度是 0。

- **pass**：必填字段都答了，第一轮没有硬伤，第二意见里该问的每一项都是「没有」，并且 resembles 是「无」。
- **fail**：第一轮已经答了的字段里有硬伤。有硬伤就不再追问，别的字段缺了也还是 fail。第二意见里某一项答了「有」，或 resembles 命中名单，也是 fail。
- **unsure**：必填字段补问之后仍缺，理由写「这几项模型没回答：…」。第二意见里某一项不是「有」或「没有」，或者 JSON 坏了、重试一次还是坏的，也是 unsure。resembles 给了名单外的具体名字，同样是 unsure。不算硬伤，也不算通过。

必填字段按图的种类分开。角色图是 text、studs、ip、mouth、antenna、characters。材质图是 text、studs、ip、characters、objects。抽帧是 text、studs、ip、sameCharacter。清晰度、构图、形状这些软分项不是必填。

返回不是合法 JSON 时，先整份重试 1 次。思考过程会去掉，拆开的 JSON 会拼回去。必填字段缺了，再补问，最多 2 次。补问会点名「上次没回答这几项：…，只补答这几项，其余不变」。补答合并进第一次的结果，已经答过的不改。已有硬伤就不再补问。补问两次还缺，就停在 unsure，不再做第二意见。第二意见自己的 JSON 坏了，也重试 1 次，还坏就是 unsure。

硬伤（字段答了才算，有一项就是 fail）：

- 任何画面：有字母、数字、汉字、商标；任何表面上有一排排圆形凸点；明显像乐高、Minecraft、吉卜力、皮克斯、迪士尼、Aardman / 小羊肖恩、纪念碑谷。
- 角色图：有嘴；头顶有比头窄的天线、旋钮、螺栓；角色不是正好 1 个。
- 材质图：有角色；叫得出名字的物件少于 3 个（几乎空白）。
- 抽帧：和共用机器人不一致。

软分只加已经回答的项。缺的那项不加分，也不扣分。挑图先在 pass 里取软分最高的。没有 pass 才在 unsure 里取，汇总页用黄条写「需要人看」，`report.json` 里 `needsHuman` 为 true。全是 fail 才改提示重出。

侧面的耳朵不是天线，单独的圆球不是凸点，黏土上的小坑不是嘴：这些写在给模型的口径里。脚本不会把模型的 true 改成 false。描述里出现「文字」「凸点」这类词，本身不再判 unsure，也不再拿掉布尔值。这些词只用来决定第二意见要多问哪几项。否定只看硬伤词前面 6 个字以内，「不是很明显」不算否定；被这扇窗盖住的词，不加进追问。

IP 不从 reason、like 这类自由文本里扫品牌名。第一轮检查表里 `ip.value` 为 true 就是硬伤，不再追问。第一轮没有硬伤、必填也齐了，就一律再发一次专项追问（第二意见）。不用先把描述洗干净才配追问。第一轮已经是 fail 的不追问。必填补问两次还缺的，停在 unsure，也不追问。

追问先让模型说那个位置有什么，再二选一答「有」或「没有」。角色图固定问三件：圆顶之上有没有比头窄的小零件（头自己的圆顶不算）、眼睛以下有没有线条或开口、画面有没有字。材质图固定问三件：叫得出名字的物件、有没有字、表面有没有成排的小圆点或小圆柱。抽帧固定问三件：有没有字、有没有成排的圆形凸起、有没有换成另一只角色。再加上 resembles，以及第一轮描述里关键词可疑、而上面没问到的那些项。任一项答「有」就是对应硬伤。全部答「没有」并且 resembles 是「无」，才是 pass。答得含糊，或不是合法 JSON、重试一次还是坏的，是 unsure。

所有 kind 都问 resembles：这张图最像哪个已知品牌、玩具、游戏、动画或作品，只写一个名字，不像就写「无」。答案是「无」「none」或「没有」不影响。用 `broll/banned-words.json` 的 `groups.ip` 做精确或包含匹配，命中就是 ip 硬伤。给了名单外的具体名字是 unsure，交给人看，理由里写它说像谁。答得含糊也是 unsure。

材质图的物件只数 `objects.names`：至少 3 个。线条、轮廓、水渍、污点，以及东西、物体、形状、图案、元素这种泛名，都不计数。`value` 和叫得出名字的个数一边少于 3、另一边不少于 3，判 unsure，不往放行改。这是结构对不上，不是靠关键词猜意思。没给 names 就补问，补问后还没有就是 unsure，不判成 0 个，也不判通过。补问给了干净的 false，不再把第一次描述里的疑点锁死；疑点改由第二意见看着图自己回答。模型把检查表拆成好几段时，脚本会拼回一个 JSON。

## 汇总页

每次跑完（或中途停下）写两份：

- `broll/styles/_drafts/<id>/review.html`：纯本地文件。最上面一行是结论和下一步命令。选中了 unsure 时，页首有一条黄底的「需要人看」。下面是每张候选的缩略图、硬伤、软分、理由、选中哪张，以及静态试拍和视频抽帧（如果做了）。
- `broll/styles/_drafts/<id>/report.json`：同一份结论的数据。选中了 unsure 时 `needsHuman` 为 true，`attention` 为「需要人看」。

这一页不能批准风格。页面上写明了下一步只能人跑。

## 人来批准

看完汇总页，人自己在终端里运行：

```
node scripts/broll/approve-style.mjs <id>
```

**AI 助手不许替人运行这条命令。** 文档、命令用法和跑完时的输出都写了这句话。不是交互终端就直接拒绝。

它先打印 `review.html` 的结论和硬伤摘要，要求输入这个 id 再回车。报告里有错误就不批准。标了「需要人看」的，还要再输入 `yes`。然后把草稿里的 `style.json` 和选中的两张参考图拷到 `broll/styles/<id>/`。`refs` 必须是 `refs/character.jpg` 和 `refs/material.jpg`，对不上不批准。做过视频试拍且通过，`status` 写 `stable`；否则写 `experimental`。`refs/README.md` 写来源和打分摘要。同名目录已经在就不覆盖。草稿留着。

新风格进风格清单，靠的是目录里有 `style.json` 这一条现有机制。不改 `broll.json` 的格式。

## 退出码

| 码 | 意思 |
|---|---|
| 0 | 只打印了请求，或已经交到等人审（没要求视频，或视频通过了） |
| 1 | 参考图挑不出来；或加了 `--video` 但视频没过；或批量里有一项失败 |
| 2 | 参数不对、写配置 3 轮没过、缺密钥、这个 id 已经发布、`state.json` 损坏或疑似被清空还没加 `--state-reset`、这个风格正在另一个进程里跑、上次视频提交没有确认结果、上次视频失败却没加 `--video-redo`、提交被明确拒绝（例如余额不足） |
| 3 | 视频还在生成。task id 留着，再跑同一条命令继续查询，不会重新提交 |
| 4 | 接口失败 |

## 看图的已知局限

描述里的硬伤词不再直接交给人看，也不会把 true 改成 false。第一轮布尔值说有，才是硬伤。说没有、但描述里带了没被否定的硬伤词，就在第二意见里多问这一项，让模型看着图自己答有或没有。IP 只看第一轮的 `ip.value`，以及第二意见的 `resembles` 是否命中名单，不从理由正文里扫品牌名。常见看错：

- 头两侧的耳朵、和头差不多宽的一块圆纸，被说成天线。
- 脸上很淡的一条弧线被漏掉；反过来，污点和指纹被当成嘴。
- 几乎空白的纸上，污渍和一根线被数成物件。模型没把必填项填进 JSON 时，脚本会补问；补问后仍缺就标 unsure，不再把缺字段当成硬伤。
- 单独的木球被当成砖面上的凸点。
- 「机器人加方块」被说成像乐高。平整的木头积木不是。
- 成片上烧进去的字幕、角标，会被判成有字。这是对的，但别拿成片抽帧当风格参考图。

核对用：

```
node scripts/broll/judge-calibrate.mjs <labels.json> --yes
```

没有 `--yes` 只打印张数和最多请求数，不调接口。加上 `--yes` 才会真的调看图接口（订阅套餐额度）。先做一次连通性试探（一张图问「图里有什么」），模型名不对就换候选再继续。密钥不打印、不写进报告。unsure 超过一半时，汇总结论写「无效：模型没答完的太多」。
