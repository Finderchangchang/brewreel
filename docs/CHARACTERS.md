# 角色档案

每个客户的讲解员单独留一份档案，后面的片子都复用这一份。客户先看角色卡，点头之后才能用在正式成片里。

卡通是「特征像」：发型、眼镜、胡子和衣服气质能对上。不是照片级的像，脸型、五官、年龄都不会像本人。肤色会记在档案里，**肤色暂不生效**，画面保持白色。

## 三种建法

1. **选预设。** 男或女，各有一套默认的发型、眼镜和衣服。
2. **自由组合。** 发型、眼镜、胡子、衣服可以自己改。衣服只有三套：深色毛衣、黑 T 恤、白衬衫。
3. **用照片。** 上传一张照片，自动挑最接近的卡通部件，再出预览。不满意可以手改。对得上的仍是上面那些特征，不是把照片变成同一个人。

照片会送到识别服务，只用来判断发型、眼镜、胡子、性别和肤色。肤色会写进档案，这一版画面上不使用。没有授权人，不能用照片建角色。预设和手改不用照片，档案里会写明「未使用客户照片」。

照片和档案放在数据目录里，不进安装文件夹。默认是当前工作目录上一级的 `brewreel-studio-data`，也可以用环境变量 `LESSON_DATA_DIR` 改。

## 客户确认

建好角色后，我们出一张角色卡：

- 一张图：8 个动作，外加张嘴、闭嘴、眨眼三种状态。人物脸朝左，底色用这个角色的默认风格。
- 一段 3 秒动画：说一句话，眨一次眼，换一次手势。

请客户看这张卡。确认之后，这个版本才能用于正式成片。

还没确认的角色，正式出片会被拒绝，并提示先出角色卡。试看可以出，画面上会有一行小字「角色未确认」。试看片不能当正式交付发出去。

## 版本

角色一旦用在成片里，用到的版本就固定下来。之后改名字、改默认风格或改形象，版本号加 1，旧版本留在档案里，已经交出去的片子不变。

讲稿里写成 `客户id/角色id@版本`。不写版本时，用当时的最新版，交付清单里记下实际用的版本、以及授权记录摘要（来源、授权人、时间、范围）。

改了形象之后要重新出角色卡，让客户再确认一次。

## 事先说清楚的限制

- 卡通是特征像，不是照片级的像。
- 换手势只在同一套衣服里换。深色毛衣的手势不会换成黑 T 恤或白衬衫的动作。
- 嘴是张开和闭上，用来表示正在说话。不是按每个字做口型。

任意衣服配任意手势，或者照片级的专属形象，这一期不做。
